**Key Technical Concepts**
-   **MongoDB as a Message Queue:** The agent implemented a custom event queue using a standard MongoDB collection and a background worker, avoiding an external dependency like Redis. Events are marked with statuses (, , , ).
-   **Centralized Serving Cache:** This is a key architectural pattern introduced to solve data consistency problems. A background process pre-calculates and stores aggregated data in a dedicated  collection. The UI is intended to read from this cache, ensuring all components display the same numbers.
-   **Hybrid RBAC Model:** The chosen security architecture. It involves syncing user identity metadata (roles, teams) from Odoo but defining the actual access control rules (e.g., Sales reps can only see their own deals) locally within the application's middleware. This provides a good balance between maintaining a single source of truth for user identity and having control over the permission logic.
-   **Declarative Middleware for Security:** The plan for the RBAC implementation is to use FastAPI middleware to automatically inject the correct data access filters into every API request, making security enforcement clean and non-invasive.
